# 规格增量：中文学习工作台

## Purpose

定义 Inkstone 在 VPS 上定时生成高质量、可追溯、互不重复的独立中文技术学习笔记，以及对应的运行诊断和安全切换行为。

## ADDED Requirements

### Requirement: 单一学习资料流水线

系统 SHALL 使用统一的学习资料采集器生成新的每日学习内容，并 SHALL 在生产切换后停止旧 GitHub Trending 与 AI Frontier 定时器继续生成旧式聚合笔记。

#### Scenario: 正常定时执行

- **WHEN** 统一 systemd 定时器到达每日计划时间
- **THEN** 系统只启动一次学习资料流水线，并由该流水线生成当日独立笔记与索引

#### Scenario: 从旧任务切换

- **WHEN** 运维人员执行文档化的切换步骤
- **THEN** 统一定时器处于启用状态，旧定时器处于停用状态，历史笔记和旧状态目录不被删除

### Requirement: 有质量下限的每日精选

系统 SHALL 每日选择 6–10 条高质量内容，默认选择 8 条，其中默认包含 4 个开源项目、2 篇技术文章和 2 个社区讨论；系统 MUST NOT 为满足数量而接受不符合候选质量或来源约束的条目。

#### Scenario: 候选池满足要求

- **WHEN** 候选池包含足够的合格仓库、文章与社区讨论
- **THEN** 系统选择 8 个互不重复的主题，并至少包含 2 个 AI 主题和 2 个后端、Java、JVM 或分布式系统主题

#### Scenario: 候选池不满足要求

- **WHEN** 任一必需来源类型的合格候选数量低于默认配额
- **THEN** 本次运行失败并记录具体缺失类型和数量，不生成低质量占位内容，也不把当日标记为成功

### Requirement: 稳定的内容去重

系统 SHALL 使用规范化内容标识对同一批次和最近 60 天内的内容去重，标识 MUST 对常见 URL 跟踪参数、尾斜杠、大小写差异和 GitHub 多入口保持稳定。

#### Scenario: 同一仓库来自多个 GitHub 入口

- **WHEN** 同一仓库同时出现在 Trending、Search 或 Release 候选中
- **THEN** 当日最多入选一个以该仓库为学习主体的条目

#### Scenario: 同一文章具有不同 URL 表示

- **WHEN** RSS 或社区入口提供仅在跟踪参数、片段或尾斜杠上不同的文章 URL
- **THEN** 系统把这些候选视为同一内容并只保留质量分最高的一项

#### Scenario: 近期内容再次出现

- **WHEN** 某一规范化内容标识已经在最近 60 天成功写入
- **THEN** 系统不再将它加入当日可选候选池

### Requirement: 独立且可追溯的中文 Markdown

系统 SHALL 为每个入选条目创建一篇独立中文 Markdown 笔记，并 SHALL 将笔记放入“技术学习资料”下对应的中文来源目录。

#### Scenario: 创建开源项目学习笔记

- **WHEN** 入选条目是 GitHub 仓库
- **THEN** 笔记包含日期、来源类型、学习方向、难度、原始链接和中文分层标签，并包含为什么值得学习、做得好的方面、核心知识点、真实代码路径导读、可迁移经验、动手练习及限制

#### Scenario: 创建文章或社区学习笔记

- **WHEN** 入选条目是技术文章或社区讨论
- **THEN** 笔记保留原始资料链接，文章说明论证与适用边界，社区讨论区分共识、争议与待验证观点

#### Scenario: 模型返回无依据内容

- **WHEN** 模型返回未知候选标识、非允许标签或不存在于已读取仓库证据中的代码路径
- **THEN** 系统拒绝或移除无依据字段，并且不会把虚构路径写入最终笔记

### Requirement: 每日导航索引

系统 SHALL 在全部独立学习笔记成功写入后创建一篇当日索引，索引 MUST 作为导航而不是重复完整报告。

#### Scenario: 索引创建成功

- **WHEN** 当日全部独立笔记均已获得 Inkstone 笔记引用
- **THEN** 索引按开源项目、技术文章和社区讨论分组，链接到每篇独立笔记，并展示学习价值、主要优点和中文标签

#### Scenario: 独立笔记尚未全部成功

- **WHEN** 任一独立笔记写入失败且无法通过同一次重试恢复
- **THEN** 系统不把当日标记为成功，并在恢复前不创建不完整的最终索引

### Requirement: 幂等和可续跑写入

系统 SHALL 在远程写入前持久化当日选择与生成结果，并 SHALL 为每篇笔记及索引使用稳定操作标识，以便失败后重试不会重复创建内容。

#### Scenario: 写入中途退出

- **WHEN** 进程在部分笔记写入后退出并于同一天重新启动
- **THEN** 系统复用原持久化载荷和操作标识，已完成写入不会生成重复笔记，剩余写入可以继续

#### Scenario: 当日已经成功

- **WHEN** 定时器或运维人员在同一天再次启动采集器
- **THEN** 系统跳过新的采集和写入，并报告当日已经完成

### Requirement: 可审计运行记录

系统 SHALL 为每次每日运行维护不含凭据的结构化记录，记录开始与结束时间、当前阶段、候选数量、选择数量、来源警告、写入数量、重试信息和最终结果。

#### Scenario: 部分来源不可用但候选充足

- **WHEN** 一个外部来源失败而其余来源仍能满足质量和配额要求
- **THEN** 系统继续生成当日内容，并在运行记录和索引采集提示中记录失败来源

#### Scenario: 运行失败

- **WHEN** 候选收集、模型生成、验证或 MCP 写入导致本次运行失败
- **THEN** 运行记录标记失败阶段和清理后的错误信息，保留可重试状态，且不记录令牌、Authorization 头或凭据文件内容

#### Scenario: 运行成功

- **WHEN** 全部独立笔记与索引均成功写入
- **THEN** 运行记录标记成功并包含最终写入数量，成功日期仅在完成后更新

### Requirement: 可验证和可回滚的运维切换

系统 SHALL 提供可重复执行的切换、检查和回滚步骤，并 MUST NOT 在切换过程中删除历史笔记或状态数据。

#### Scenario: 重复执行切换

- **WHEN** 运维人员对已经切换完成的主机再次执行安装或切换步骤
- **THEN** systemd 单元保持目标状态，不产生额外定时器或破坏现有凭据和状态

#### Scenario: 回滚统一采集器

- **WHEN** 新流水线验证失败且运维人员执行回滚步骤
- **THEN** 可以停用统一定时器并恢复先前选择的旧定时器，运行状态和历史笔记仍然保留用于诊断
