# 设计：学习进度与复习工作台

## Context

学习采集器已经在每篇笔记的 Front Matter 和正文末尾写入中文分层标签，包括 `学习状态/待实践`。Inkstone 的 `NoteSummary.tags` 会从 Markdown 中解析标签，因此工作台可以直接使用现有同步数据完成分类，不需要新增服务端查询或数据库字段。

## Decisions

### 1. 标签是学习状态的唯一事实来源

第一版支持 `学习状态/待实践`、`学习状态/学习中`、`学习状态/待复习`、`学习状态/已掌握`。状态解析按固定优先级处理，避免异常笔记同时出现在多列；未知 `学习状态/*` 标签进入“需整理”而不是静默丢失。

### 2. 第一批先做只读看板

第一批只实现分类、统计、筛选和打开笔记，先证明导航价值和移动端布局。状态写入放在第二批，并复用现有离线写入队列，避免用旁路 API 破坏冲突恢复语义。

### 3. 面板而不是新的顶级路由

工作台使用现有全屏弹层模式，通过 `PanelName` 管理，保持 `/n/:id` 深链接和普通笔记导航不变。桌面显示多列摘要，窄屏改为单列分组。

### 4. 不自动清理异常状态

多状态、未知状态或元数据缺失只在 UI 中标记，第一批不自动重写用户内容。后续状态迁移只在用户明确点击时修改当前笔记。

### 5. 复习日期保留在 Markdown

后续使用 Front Matter 的 `复习日期` 和 `上次学习` 字段形成到期队列；排序规则必须是确定性的，并公开显示“已到期/今天/未来”原因。

## Risks

- 普通笔记可能手工使用同名标签：工作台只依据明确的 `学习状态/` 前缀纳入，这是用户可见且可撤销的选择。
- 同一笔记含多个状态：使用优先级归类并显示异常标志，避免重复计数。
- 大量笔记导致面板卡顿：第一版基于已同步摘要做纯内存分组，不读取全部正文。
- 状态写入破坏正文：第二批必须先用纯函数测试 Front Matter 和自动标签的最小替换，再接入 store。

## Rollout

1. 建立纯分类器和固定夹具测试。
2. 增加工作台面板、侧边栏入口与响应式布局。
3. Grill Me 第一批复审分类规则、空状态、可访问性和非学习笔记隔离。
4. 第二批实现显式状态迁移和冲突安全写入。
5. 第三批实现复习日期、到期队列并完成全量验证。
