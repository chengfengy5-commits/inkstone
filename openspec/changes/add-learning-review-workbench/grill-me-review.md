# Grill Me Review

## 第一批质询结论

1. 普通笔记只有在标签以 `学习状态/` 开头时才会被纳入；正文里出现状态词或普通标签不会误入。
2. 同一笔记只分类一次。多个不同状态进入唯一的“需整理”泳道，重复的同名状态会去重后进入正常泳道。
3. 未知状态不会隐藏，也不会猜测映射；统一进入“需整理”并展示原始状态，方便人工修正。
4. 分类器先排除 `isArchived` 或 `deletedAt` 非空的摘要，不会污染计数。
5. 工作台只消费现有 `NoteSummary[]`，没有调用正文读取接口；卡片打开时才沿用原有 `openNote` 流程加载目标笔记。
6. 卡片先关闭 Panel，再调用既有 notes store 的 `openNote(id)`。组件测试和手机端浏览器验收均证明能打开对应笔记。
7. 手机窄屏实测采用单列纵向泳道，标题、计数和关闭按钮无重叠，没有横向溢出；所有入口与卡片使用现有可点击控件尺寸。桌面布局由响应式断点切换为双列/五列，组件结构不复制移动端逻辑。
8. 第一批仅增加纯分类器、客户端面板、入口和文案；没有数据库迁移、后台提醒或采集改动。

## 第二批质询结论

1. 状态切换使用原生下拉框，支持键盘和触屏；异常笔记必须明确选择目标状态，不做自动猜测。
2. 未打开的笔记通过 `openNote(id, { navigate: false })` 复用缓存恢复、离线日志和服务端读取逻辑，不改变当前工作区或深链接。
3. 写入仍调用 store 的 `editContent`，继续走现有本地持久化、自动保存、冲突重放和失败回滚链路，没有旁路请求。
4. 状态重写只处理 `学习状态/*` 标签：已有目标状态时删除冲突状态，没有状态时追加一个正文标签；其他 Front Matter、正文、链接和标签保持不变。
5. 后台读取失败时不写入半成品，并显示错误反馈；切换期间控件禁用，避免同一笔记重复提交。
